Technical Follow-ups (High-Level)

These are production verification and configuration tasks. Detailed specs remain in the June priority page.

Supabase & Data Layer

  • Apply RLS migration: deploy supabase-rls-learning-items.sql to production before Phase 2 learner data lands.
  • Validate catalog sync: verify learning_items table populates correctly from the Brightspace Course Offering API.

Production Login & Authentication

  • Configure production environment: set NEXT_PUBLIC_OAUTH_TENANT, NEXT_PUBLIC_OAUTH_REDIRECT_URI, and related OAuth environment variables on the deployed Hub.
  • End-to-end Brightspace sign-in test: verify learners can sign in through the real Brightspace OAuth flow on the deployed Learning Hub (no demo mode).
  • Session & token verification: confirm session cookies, token refresh, and /api/me identity endpoint work correctly in production.

Service-User & Server-to-Server OAuth

  • Service-user sync app registration: finalize the D2L Manage Extensibility app registration for server-to-server OAuth, including JWKS URL and required scopes.
  • Client Credentials flow test: validate JWT client assertion generation and access token requests.

D2L Ticket Queue

  • Attribute limit clarification: get written confirmation: 10 or 50 total attributes? How many can be multi-value? Which attributes can drive Learning Groups?
  • Vanity URL: domain selection → submit to D2L for internal request and DNS records.
  • Custom email templates: review and approve branded email notifications for learner events.
  • Closure call: confirm all implementation items are covered and transition to standard support.

What Happened During the Delay

The June-to-August extension was used productively. Here's what the team built instead of waiting:

  • Done Brightspace Manager command center: admin dashboard for sync monitoring, learner data verification, and operations troubleshooting.
  • Done Brightspace admin MCP server: Claude integration for automated data inspection, diagnostics, and admin tasks.
  • Done Hub login is real: the Learning Hub learner sign-in now uses end-to-end Brightspace OAuth (no demo-only mode for live usage).
  • Done Service user created: the non-human Brightspace account for server-to-server sync is established and ready for app registration.
  • Done Ops & integration docs: credential rotation runbook and assumption-testing checklist drafted (local operations runbook, not published).
